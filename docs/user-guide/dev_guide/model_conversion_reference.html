DL Streamer developer reference

Model Conversion Reference

Reproducible package installations and commands for converting models from their original framework format to OpenVINO™ Intermediate Representation (IR).

Conversion methods Ultralytics YOLO Optimum Intel GenAI VLMs TIMM YOLOv7 PaddleOCR

Conversion Methods

Each conversion produces an .xml topology file and matching .bin weights file. Package commands assume an isolated Python environment. The table starts with broad conversion methods and narrows to model-specific overrides.

Conversion Notes

Ultralytics YOLO

The model argument may be a supported Ultralytics model name, which is downloaded automatically, or a local .pt checkpoint. Replace yolo11n.pt with another supported checkpoint.

TaskExample model
Object detectionyolo11n.pt
Instance segmentationyolo11n-seg.pt
Pose estimationyolo11n-pose.pt
Oriented object detectionyolo11n-obb.pt
Image classificationyolo11n-cls.pt

Precision options

PrecisionExport argumentNotes
FP32NoneThe exporter default; omit half and int8.
FP16half=TrueCompresses model weights to FP16.
INT8int8=TruePerforms INT8 quantization. NNCF is required and a calibration dataset may be downloaded.

Export INT8 with the CLI:

yolo export model=yolo11n.pt format=openvino dynamic=True int8=True

Or export a local checkpoint with the Python API:

from ultralytics import YOLO

model = YOLO("/path/to/custom.pt")
model.export(format="openvino", dynamic=True, half=True)

Do not enable half and int8 together.

Legacy YOLOv5: checkpoints from ultralytics/yolov5 are not the same family as YOLOv5u checkpoints.

See YOLO Models and the Ultralytics OpenVINO integration.

Hugging Face Models Supported by Optimum Intel

Optimum Intel supports OpenVINO export for many architectures from Transformers, Diffusers, and Sentence Transformers. Check the supported model architectures before conversion. --model accepts a Hugging Face Hub model ID or local model directory.

For Hub models, Optimum usually infers the task. Set --task explicitly when inference is ambiguous and always set it for a local model.

PrecisionArgumentNotes
FP32--weight-format fp32Retains full-precision weights.
FP16--weight-format fp16Compresses model weights to FP16.
INT8--weight-format int8Applies weight-only INT8 quantization.
INT4--weight-format int4Applies weight-only INT4 quantization, primarily for large generative models.

For full INT8 quantization of weights and activations, use --quant-mode int8 and provide a representative dataset when required. Authenticate with Hugging Face before exporting gated or private models.

OpenVINO GenAI Vision-Language Models

The model groups and overrides follow the OpenVINO GenAI supported-models table. Fara-7B, Gemma 3, Gemma 3n, and Gemma 4 repositories are gated.

The Qwen3.5, Qwen3.6, Gemma 4, and Gemma 4 Unified rows reproduce OpenVINO GenAI development configurations rather than released dependency sets. Their source exporter is installed with --no-deps, so pip check reports an intentional conflict between Optimum Intel 2.0.0 metadata and Transformers 5.x. Prefer a compatible released package when available.

--trust-remote-code executes code supplied by the model repository. Use it only after reviewing and pinning a trusted model revision.

VideoChat-Flash is downloaded from ModelScope before local export and supports video, but not image, input at runtime. Phi-4 Multimodal uses patched files from Hugging Face discussion 78. For Phi-3 Vision runtime, take the generation EOS token from the tokenizer because model configurations are inconsistent.

Conversion support does not guarantee that a DL Streamer element implements the required inputs and post-processing. Check Supported Models, Transformer Models, and the Optimum Intel export guide.

TIMM Image Classification

Pass the model's Hugging Face repository ID to --model; it is not always identical to the short name accepted by the TIMM Python API. For example, mobilenetv3_small_100 is hosted as timm/mobilenetv3_small_100.lamb_in1k.

The output directory contains the OpenVINO IR and configuration files required for inference.

Model-Specific Details

YOLOv7

Prepare the original repository and checkpoint before running the package installation and conversion commands from the table:

git clone https://github.com/WongKinYiu/yolov7.git
cd yolov7
wget https://github.com/WongKinYiu/yolov7/releases/download/v0.1/yolov7.pt
sed -i 's/torch\.load(w, map_location=map_location)/torch.load(w, map_location=map_location, weights_only=False)/g' models/experimental.py

The loader adjustment is required by PyTorch 2.6 and newer. Only load a checkpoint from a trusted source when weights_only=False is used.

When using the IR with gvadetect, specify coco_80cl.txt as the labels file and yolo-v7.json as the model-proc file.

PaddleOCR

PaddleOCR requires a PaddlePaddle-to-ONNX conversion before ovc. The table command targets PP-OCRv4 models containing inference.pdmodel and inference.pdiparams.

Newer exports may contain inference.json instead of inference.pdmodel; pass the filename present in the downloaded model. Keep the corresponding character dictionary and model configuration with the IR because post-processing needs them to decode output tokens.
